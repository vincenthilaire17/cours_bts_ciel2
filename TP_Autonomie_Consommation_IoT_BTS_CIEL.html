PARTIE 1 : Modélisation sous Proteus VSM — Modes de Veille, Watchdog (WDT) & Power Gating ⏱ Durée : 1h00

1.1. Rappels fondamentaux : Veille du Microcontrôleur et Rôle Double du Watchdog

Un microcontrôleur ATmega328P (cœur de l'Arduino Nano) cadencé à 16 MHz consomme environ 12 à 15 mA à lui seul lorsqu'il exécute une attente active bloquante avec delay() : le processeur tourne à plein régime pour ne rien faire ! L'architecture AVR propose plusieurs modes de sommeil (registre SMCR), dont deux extrêmes :

  • SLEEP_MODE_IDLE (Sommeil léger) : coupe l'horloge du CPU mais laisse tourner l'oscillateur 16 MHz, l'UART, le SPI, l'ADC et les Timers (millis() continue). Économie modeste (~30 à 40 %).
  • SLEEP_MODE_PWR_DOWN (Veille profonde) : arrête l'oscillateur principal 16 MHz et tous les périphériques synchrones. La consommation du cœur ATmega328P nu chute sous 5 µA (soit un facteur ÷ 3000) si le convertisseur analogique-numérique (ADC) est préalablement désactivé !
🐕 Le Watchdog Timer (WDT) : Chien de Garde Sécurité ET Réveil Cyclique Autonome

Le Watchdog Timer est un compteur matériel indépendant cadencé par son propre oscillateur RC interne ultra-sobre à 128 kHz (qui continue de fonctionner même en mode PWR_DOWN). Selon la configuration du registre WDTCSR, il remplit deux missions vitales en électronique embarquée :

  1. Mission Sûreté de fonctionnement (Mode System Reset : WDE = 1, WDIE = 0) : Si un parasite électromagnétique ou un périphérique défaillant fige le programme dans une boucle infinie (ex. while(!radio.ready());), le CPU ne remet plus à zéro le chien de garde (wdt_reset()). À l'expiration du délai (de 16 ms à 8 s), le WDT force un Reset matériel automatique, évitant que la carte bloquée ne vide toute la batterie sur le terrain !
  2. Mission Économie d'énergie (Mode Interrupt Wake-Up : WDIE = 1, WDE = 0) : Comme tous les Timers classiques sont éteints en SLEEP_MODE_PWR_DOWN, le WDT génère une interruption de réveil (ISR(WDT_vect)) toutes les 1 à 8 secondes sans rebooter la carte. Pour dormir 10 minutes (600 s), il suffit d'enchaîner 75 × 8 s de sommeil profond !
⚠️ Piège d'Électronicien : Endormir le MCU ne suffit pas (Power Gating & Rétro-alimentation) !

Si vous endormez l'ATmega328P à 5 µA mais laissez votre module Bluetooth ou capteur branché directement sur le rail +5V, ce module continue de consommer 15 à 35 mA en permanence ! Il faut impérativement couper son alimentation via un transistor MOSFET ou bipolaire piloté par une broche GPIO : c'est le Power Gating.

Attention au « Back-Powering » (alimentation fantôme par l'UART) : Au repos, une broche série TX est à l'état logique HAUT (+5V). Si vous coupez l'alimentation du module radio sans forcer les broches TX/RX de l'Arduino à LOW (ou INPUT), le courant de la broche TX va fuir à travers les diodes de protection ESD internes du module radio et continuer à l'alimenter partiellement (5 à 12 mA perdus) !

1.2. Programme de référence C++ AVR (Veille Profonde + Watchdog + Power Gating)

Ce programme n'utilise aucune bibliothèque externe à télécharger : il exploite directement les registres officiels AVR (<avr/sleep.h> et <avr/wdt.h>) nativement inclus dans Arduino IDE et simulables sous Proteus VSM :

#include <avr/sleep.h>
#include <avr/wdt.h>
#include <SoftwareSerial.h>

const uint8_t PIN_BT_RX   = 2;   // D2 : RX SoftwareSerial
const uint8_t PIN_BT_TX   = 3;   // D3 : TX SoftwareSerial
const uint8_t PIN_PWR_RAD = 4;   // D4 : Grille du MOSFET 2N7000 (Power Gating Radio)
const uint8_t PIN_TRIG_AD3= 7;   // D7 : Repère synchro pour l'oscilloscope AD3 (Voie 2)

SoftwareSerial radioSerial(PIN_BT_RX, PIN_BT_TX);
volatile bool reveil_wdt = false;

// Vecteur d'interruption déclenché par l'oscillateur 128 kHz du Watchdog
ISR(WDT_vect) {
  wdt_disable();          // Coupe le WDT dès le réveil
  reveil_wdt = true;
}

// Endort le cœur ATmega328P en veille profonde pendant 8 secondes
void dormir_profond_8s() {
  ADCSRA &= ~(1 << ADEN); // 1. Coupe l'ADC interne (~250 µA économisés !)

  cli();                  // 2. Séquence atomique d'armement du Watchdog (8,0 s)
  MCUSR &= ~(1 << WDRF);
  WDTCSR |= (1 << WDCE) | (1 << WDE);
  WDTCSR  = (1 << WDIE) | (1 << WDP3) | (1 << WDP0); // WDIE=1 (Interruption), WDE=0
  sei();

  set_sleep_mode(SLEEP_MODE_PWR_DOWN);
  sleep_enable();
  sleep_bod_disable();    // 3. Désactive le Brown-Out Detector durant le sommeil
  sleep_cpu();            // --- ARRET CPU 16 MHz : Attente passive (~5 µA cœur) ---

  sleep_disable();        // --- REPRISE ICI APRES L'INTERRUPTION WDT ---
  ADCSRA |= (1 << ADEN);  // Réactive l'ADC pour la prochaine mesure capteur
}

void setup() {
  pinMode(PIN_PWR_RAD, OUTPUT);
  pinMode(PIN_TRIG_AD3, OUTPUT);
  Serial.begin(115200);
}

void loop() {
  // --- PHASE ACTIVE : Alimentation Radio + Mesure + Transmission ---
  digitalWrite(PIN_TRIG_AD3, HIGH);  // Front montant de trigger pour l'AD3
  digitalWrite(PIN_PWR_RAD, HIGH);   // Alimente le module radio via le MOSFET
  delay(150);                        // Temps de stabilisation du module radio

  radioSerial.begin(9600);
  radioSerial.println("$NODE01;T=21.4;V=4.98#"); // Trame télémétrie (22 octets)
  delay(40);                         // Fin d'émission UART

  // --- PREPARATION A LA VEILLE : Eviter toute rétro-alimentation (Back-Powering) ---
  radioSerial.end();
  pinMode(PIN_BT_TX, INPUT);         // Haute impédance (0 fuite par les diodes ESD !)
  pinMode(PIN_BT_RX, INPUT);
  digitalWrite(PIN_PWR_RAD, LOW);    // Coupe l'alimentation du module radio
  digitalWrite(PIN_TRIG_AD3, LOW);   // Fin de la fenêtre active

  // --- PHASE DE SOMMEIL PROFOND (ex: 1 cycle de 8s pour le test en TP) ---
  dormir_profond_8s();
}

PARTIE 2 : Métrologie par Shunt Différentiel (Digilent AD3) & Audit de la Carte Arduino Nano ⏱ Durée : 1h00

2.1. Pourquoi un multimètre échoue-t-il sur un système IoT communicant ?

Un multimètre numérique standard rafraîchit son affichage 2 à 3 fois par seconde en intégrant le signal sur plusieurs centaines de millisecondes. Or, un émetteur radio Wi-Fi ou Bluetooth génère des pics de courant impulsionnels (bursts) de quelques centaines de microsecondes à quelques dizaines de millisecondes : le multimètre les écrase complètement !

Pour capturer le profil réel i(t), on insère en série sur l'alimentation une résistance de mesure (Shunt) Rshunt et l'on mesure la tension à ses bornes avec l'entrée analogique différentielle de l'oscilloscope Digilent Analog Discovery 3 :

Loi d'Ohm instantanée (Voie Math WaveForms) : i(t) = ushunt(t)Rshunt = V1+(t) − V1−(t)Rshunt  | Charge électrique : Q = ∫ i(t) dt ≈ Imoy × Δt  [en C ou mA·s]
🔬 Avantage décisif du Digilent Analog Discovery 3 & Choix de Rshunt (Burden Voltage)
  • Entrées différentielles vraies : Contrairement à un oscilloscope de table classique dont la pince crocodile noire des sondes BNC est reliée à la Terre du secteur 230 V (risque de court-circuit franc si on la pince côté +5V !), les entrées 1+ (Orange) et 1- (Orange/Blanc) de l'AD3 forment un amplificateur différentiel flottant haute impédance (1 MΩ). Toujours relier néanmoins un fil GND noir (▼) de l'AD3 à la masse du montage pour fixer le mode commun !
  • Compromis sur la tension de chute (Burden Voltage) :
    • Avec Rshunt = 10 Ω : excellente sensibilité pour l'Arduino Nano et la veille (1 mA donne 10 mV, très lisible sur l'AD3). Mais si un ESP32 en Wi-Fi appelle brutalement 300 mA, la chute de tension atteint 10 Ω × 0,3 A = 3,0 V ! La carte ne reçoit plus que 2,0 V et plante en Brown-Out Reset !
    • Avec Rshunt = 1 Ω : à 300 mA, la chute n'est que de 0,3 V : le module Wi-Fi ou LoRa fonctionne parfaitement sans décrocher !

PARTIE 3 : Campagne Comparative Multi-Radios au Banc — Bluetooth vs Wi-Fi vs LoRa 868 MHz ⏱ Durée : 1h45

Pour comparer équitablement trois technologies sans fil aux débits et portées radicalement différents, l'ingénieur ne compare pas uniquement le courant instantané en mA : il évalue l'énergie totale en millijoules (mJ) nécessaire pour transmettre une même trame utile de télémétrie (ex. 16 à 22 octets) depuis la sortie de veille jusqu'au retour en veille !

Charge consommée par cycle : Qcycle = Imoy_cycle × Δtactif  [mC] = Imoy_cycle [mA] × Δtactif [s]3,6  [μAh]  | Énergie : Ecycle = Ualim × Imoy_cycle × Δtactif  [mJ]

3.1. Protocole expérimental des 3 mesures au banc AD3

Sécurité calibre Shunt : Passez impérativement sur la résistance Rshunt = 1 Ω (et mettez à jour la formule WaveForms Math 1 : C1 / 1) avant de mesurer le Wi-Fi et le LoRa afin de supporter les appels de courant jusqu'à 350 mA sans chute de tension excessive.

  1. Mesure A — Bluetooth (Arduino Nano + Module Grove Bluetooth) :
    • Relevez le profil de courant du module Bluetooth dans 3 sous-états : Non connecté (LED clignotante / Inquiry Scan), Appairé au repos (LED fixe), et lors de l'envoi de la trame de 22 octets $NODE01;T=21.4;V=4.98# vers votre smartphone.
    • Vérifiez l'effet du Power Gating MOSFET développé en Partie 1 sur la consommation entre deux envois.
  2. Mesure B — Wi-Fi 802.11 (XIAO ESP32-S3 ou Raspberry Pi Pico 2 W) :
    • Téléversez le croquis de cycle Wi-Fi ci-dessous qui réveille le microcontrôleur, s'associe au point d'accès WPA2 de la salle, obtient une IP par DHCP, émet un datagramme UDP (22 octets), puis plonge en Deep Sleep pendant 10 secondes :
    // Croquis de profilage énergétique Wi-Fi (Compatible ESP32 / ESP32-S3)
#include <WiFi.h>
#include <WiFiUdp.h>

const char* SSID = "SSID_SALLE_TP";
const char* PASS = "MOT_DE_PASSE";
const int   PIN_TRIG = 2; // Broche D1/GPIO2 reliée à la voie 2+ de l'AD3
WiFiUDP udp;

void setup() {
  pinMode(PIN_TRIG, OUTPUT);
  digitalWrite(PIN_TRIG, HIGH);         // Début de fenêtre temporelle AD3

  WiFi.mode(WIFI_STA);
  WiFi.begin(SSID, PASS);
  uint32_t t0 = millis();
  while (WiFi.status() != WL_CONNECTED && (millis() - t0) < 8000) {
    delay(10);
  }

  if (WiFi.status() == WL_CONNECTED) {
    udp.beginPacket("192.168.1.255", 5005);
    udp.print("$NODE01;T=21.4;V=4.98#"); // Même charge utile de 22 octets !
    udp.endPacket();
    delay(20);
  }

  WiFi.disconnect(true);
  WiFi.mode(WIFI_OFF);
  digitalWrite(PIN_TRIG, LOW);          // Fin de fenêtre active

  esp_sleep_enable_timer_wakeup(10ULL * 1000000ULL); // Deep Sleep 10 s
  esp_deep_sleep_start();
}
void loop() {}
    • Déclenchez l'AD3 sur le front montant de PIN_TRIG (base de temps large : 500 ms/div). Relevez la durée totale Δtactif d'association + envoi, le pic maximal Imax, le courant moyen pendant la fenêtre active, et le courant résiduel en Deep Sleep.
  3. Mesure C — LoRa 868 MHz (Module LoRa de la salle : Wio-E5 / LoRa-E5 AT ou SX1276 SPI) :
    • Configurez une émission LoRa brute point-à-point sur 868,1 MHz (puissance +14 dBm, largeur de bande BW = 125 kHz) avec la même charge utile de 22 octets :
      • Sur module UART AT (type Grove Wio-E5) : AT+MODE=TEST → AT+TEST=RFCFG,868.1,SF7,125,8,8,14,ON,OFF,OFF → AT+TEST=TXLRSTR,"$NODE01;T=21.4;V=4.98#", puis passage en veille AT+LOWPOWER.
      • Sur module SPI SX1276/RFM95 (bibliothèque LoRa.h) : LoRa.setSpreadingFactor(7);, envoi du paquet LoRa.beginPacket(); ... LoRa.endPacket(); puis LoRa.sleep();.

PARTIE 4 : Audit de la Powerbank Varta 5000 mAh — Du Marketing des mAh à la Physique des Wh & Auto-Shutoff ⏱ Durée : 1h00

4.1. Le premier piège industriel : « 5000 mAh » sous quelle tension ?

Retournez votre Powerbank Varta 5000 mAh et lisez attentivement les inscriptions réglementaires gravées en petits caractères sur la coque. Une Powerbank USB contient un accumulateur Lithium-Polymère (Li-Po) dont la tension nominale électrochimique est de 3,7 V (variant de 4,2 V pleine charge à ~3,0 V déchargée). Pour délivrer du 5,0 V sur la prise USB, un convertisseur à découpage élévateur (hacheur Boost) est interposé en permanence :

Figure 4 : Chaîne énergétique interne de la Powerbank Varta 5000 mAh — Conservation de l'énergie en Wh et coupure automatique de fin de charge
Énergie nominale stockée : Ecell = Ccell × Ucell = 5,0 Ah × 3,7 V = 18,5 Wh  ⇒ Capacité utile côté 5 V : C5V = Ecell × ηboost5,0 V

4.2. Le second piège industriel : la coupure automatique (Auto-Shutoff) en mode veille

Une Powerbank du commerce est conçue pour charger un smartphone (qui réclame 500 mA à 2400 mA). Lorsque la batterie du smartphone est pleine, le courant appelé tombe sous un seuil Iseuil (typiquement 50 à 80 mA). Afin de ne pas vider inutilement la cellule Li-Po dans le courant de repos de son propre hacheur Boost, la Powerbank coupe totalement sa sortie 5 V au bout d'un délai Ttimeout (typiquement 20 à 35 s).

Or, notre balise IoT optimisée ne consomme que quelques milliampères en veille : la Powerbank « croit » qu'aucun appareil n'est branché et s'éteint définitivement !

Travail expérimental demandé sur la Powerbank Varta 5000 mAh :

  1. Inspection réglementaire : Relevez sur la coque de la Powerbank Varta la capacité nominale cellule (3,7 V), l'énergie en Wh, et la capacité effective restituée sous 5 V inscrite par le constructeur. Déduisez-en le rendement global ηboost annoncé par Varta.
  2. Caractérisation expérimentale de l'Auto-Shutoff :
    • Alimentez votre montage Arduino Nano (programme de veille profonde de la Partie 1) avec la Powerbank Varta à travers l'AD3. Appuyez sur le bouton de marche de la Powerbank et chronométrez précisément le délai Ttimeout au bout duquel la tension +5V s'effondre à 0 V.
    • À l'aide des résistances du kit (1 kΩ, 220 Ω, 100 Ω, 68 Ω, 47 Ω — vérifiez la puissance dissipée P = U²/R ≤ 0,5 W pour les résistances 1/4 W ou câblez deux résistances de 100 Ω en parallèle pour obtenir 50 Ω sans échauffement !), encadrez expérimentalement le courant minimal continu Iseuil qui empêche la Powerbank Varta de se couper.
  3. Conception et test d'un circuit « Keep-Alive » (Maintien en vie impulsionnel) :
    • Pour empêcher l'extinction sans gaspiller 70 mA en continu, câbez une résistance d'appel (ex. deux résistances de 100 Ω en parallèle = 50 Ω, soit une impulsion de 100 mA sous 5 V) commutée par un transistor MOSFET/NPN sur la broche D5.
    • Modifiez votre boucle de sommeil Watchdog pour générer une brève impulsion de 50 ms à 100 ms sur D5 toutes les 8 s (ou 16 s si Ttimeout > 20 s). Vérifiez que la Powerbank Varta ne s'éteint plus jamais, même après 3 minutes !
