TP : Déploiement, Sécurisation (HTTPS) et Analyse Réseau de la Caméra XIAO ESP32S3

⏱ Durée : 2h45 (TP complet avec extension HTTPS) 🎯 Cible : Seeed Studio XIAO ESP32S3 Sense 👥 Matières : Cybersécurité, Réseaux, Électronique 🛡 Wireshark & Outils F12
📋 Contexte & Objectifs du TP

Ce travail pratique aborde le cycle complet de mise en service d'un objet connecté industriel sur microcontrôleur Seeed Studio XIAO ESP32S3 Sense : depuis son raccordement dynamique au réseau Wi-Fi par portail captif, jusqu'à l'audit de vulnérabilité sous Wireshark et sa sécurisation par chiffrement TLS/HTTPS (port 443).

1. Objectifs Pédagogiques et Matériel

1.1. Objectifs du TP

  • 1. Réseau & Provisionnement : Provisionnement automatique d'un système embarqué IoT via un portail captif (basculement dynamique du Mode Point d'Accès AP vers le Mode Station STA avec la bibliothèque WiFiManager).
  • 2. Serveur Web Embarqué : Hébergement d'un serveur Web HTTP délivrant une interface de commande et le contrôle d'actionneurs (LED intégrée).
  • 3. Analyse de Trafic HTTP : Interception de trames, filtrage de paquets sous Wireshark et outils de développement navigateur (F12), décodage des couches du modèle OSI.
  • 4. Cybersécurité & HTTPS : Implémentation d'un serveur sécurisé (TLS/SSL) avec certificat X.509 et clé privée au format PEM, mise en évidence de la résistance au reniflage réseau (sniffing).

1.2. Matériel et Logiciels

  • Matériel : Module Seeed Studio XIAO ESP32S3 Sense avec module caméra OV2640/OV3660 + câble USB-C.
  • Poste de travail : PC sous Windows ou Linux disposant d'une carte réseau Wi-Fi.
  • Environnement de dev : Arduino IDE (avec BSP ESP32 v3.x installé) et bibliothèque WiFiManager (par tzapu).
  • Logiciel d'analyse : Wireshark (analyseur de protocole réseau) et navigateur Web (Chrome, Edge ou Firefox).

2. PARTIE 1 : Provisionnement Wi-Fi Dynamique (HTTP)

Le système embarqué doit pouvoir s'intégrer à n'importe quel réseau Wi-Fi sans nécessiter la recompilation du code source. Lors du premier démarrage (ou en cas d'échec de connexion), l'ESP32 bascule automatiquement en mode Point d'Accès (AP) sous le nom AutoConnectAP. L'utilisateur s'y connecte depuis son smartphone ou PC pour sélectionner le réseau local et saisir la clé de sécurité via un portail captif.

Figure 1 : Interface du portail captif WiFiManager généré par l'ESP32

📌 Configuration Requise dans Arduino IDE
  • Carte sélectionnée : XIAO_ESP32S3 dans le menu Outils > Type de carte > esp32.
  • PSRAM activée : OPI PSRAM (Obligatoire pour l'allocation de la mémoire vidéo et des buffers SSL).
  • Bibliothèque requise : WiFiManager by tzapu (à installer via le Gestionnaire de bibliothèques).

2.2. Travail Pratique & Manipulation du Portail Captif

  1. Connexion au Point d'Accès : Depuis votre poste, scannez les réseaux Wi-Fi et connectez-vous au réseau généré par votre module (SSID : AutoConnectAP, mot de passe : password). Adaptez le SSID pour le différencier de celui de vos camarades !
  2. Saisie des Identifiants : Le portail captif s'ouvre automatiquement dans votre navigateur (sinon naviguez vers http://192.168.4.1). Cliquez sur Configure WiFi, sélectionnez le réseau Wi-Fi de la salle et saisissez la clé de sécurité.
  3. Validation : Observez dans le moniteur série le basculement en mode Station (STA) et relevez l'adresse IP attribuée par le serveur DHCP.

2.3. Déploiement du Serveur Web HTTP de Contrôle de la LED

Fichier Arduino : 02_xiao_webserver_led.ino (Code Complet WebServer) Partie 1.2 
#include <WiFi.h>
#include <WebServer.h>
#include <WiFiManager.h>

// Instanciation du serveur Web HTTP sur le port standard 80
WebServer server(80);

// Définition de la LED intégrée sur XIAO ESP32-S3 (Pin 21, Active LOW / Anode commune)
const int PIN_LED = 21;

// --- 1. Fonction qui génère la page d'accueil HTML ---
void handleRoot() {
  String html = "<!DOCTYPE html><html><head><meta charset='utf-8'>";
  html += "<meta name='viewport' content='width=device-width, initial-scale=1.0'>";
  html += "<title>Contrôle LED - XIAO ESP32S3</title>";
  html += "<style>";
  html += "body { font-family: Arial, sans-serif; text-align: center; margin-top: 50px; background-color: #f7f9fa; }";
  html += ".btn { display: inline-block; padding: 15px 25px; font-size: 18px; color: white; border: none; border-radius: 8px; text-decoration: none; margin: 10px; cursor: pointer; }";
  html += ".btn-on { background-color: #4CAF50; }";
  html += ".btn-off { background-color: #f44336; }";
  html += "</style></head><body>";
  html += "<h1>Contrôle de la LED (XIAO ESP32S3)</h1>";
  html += "<a href='/led/on'><button class='btn btn-on'>Allumer</button></a>";
  html += "<a href='/led/off'><button class='btn btn-off'>Éteindre</button></a>";
  html += "</body></html>";

  server.send(200, "text/html", html);
}

// --- 2. Action pour allumer la LED (Pin 21 à LOW) ---
void handleLedOn() {
  digitalWrite(PIN_LED, LOW);
  server.sendHeader("Location", "/");
  server.send(303); // Redirection HTTP
}

// --- 3. Action pour éteindre la LED (Pin 21 à HIGH) ---
void handleLedOff() {
  digitalWrite(PIN_LED, HIGH);
  server.sendHeader("Location", "/");
  server.send(303);
}

void setup() {
  Serial.begin(115200);

  // Configuration de la LED
  pinMode(PIN_LED, OUTPUT);
  digitalWrite(PIN_LED, HIGH); // Éteinte au démarrage

  // Connexion Wi-Fi dynamique
  WiFiManager wm;
  wm.autoConnect("XIAO-SETUP-AP", "password");

  Serial.println("[OK] Wi-Fi Connecté.");
  Serial.print("Serveur Web accessible à l'adresse : http://");
  Serial.println(WiFi.localIP());

  // Définition des routes du serveur Web
  server.on("/", handleRoot);
  server.on("/led/on", handleLedOn);
  server.on("/led/off", handleLedOff);

  // Démarrage du serveur
  server.begin();
  Serial.println("[OK] Serveur Web HTTP démarré sur port 80.");
}

void loop() {
  // Écoute permanente des requêtes clientes entrantes
  server.handleClient();
}

3. PARTIE 2 : Analyse de Trame HTTP et Extraction d'une Requête

🎯 Objectif de la Partie 2

Intercepter, analyser et décoder les requêtes HTTP envoyées au microcontrôleur XIAO ESP32-S3 lors de l'activation/désactivation de la LED intégrée via l'interface web.

3.1. Analyse via l'Outil de Développement du Navigateur (Touche F12)

Cette méthode permet une observation rapide des requêtes HTTP échangées au niveau de la couche applicative sans installer de logiciel tiers :

  1. Ouvrir le navigateur web (Google Chrome, Firefox ou Microsoft Edge).
  2. Accéder à l'adresse IP du XIAO ESP32-S3 (ex: http://192.168.1.50).
  3. Ouvrir les outils de développement en appuyant sur F12 (ou Clic droit > Inspecter).
  4. Sélectionner l'onglet Réseau (Network).
  5. Vérifier que l'enregistrement du trafic est actif (voyant rouge présent).
  6. Cliquer sur le bouton Allumer ou Éteindre sur la page Web.
  7. Sélectionner la requête interceptée (on ou off) dans la liste pour en examiner le détail.

Structure de la trame HTTP interceptée :

Requête HTTP envoyée par le Client (Navigateur) :
GET /led/on HTTP/1.1
Host: 192.168.1.50
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36
Accept: text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8
Referer: http://192.168.1.50/

Réponse HTTP renvoyée par le Serveur (ESP32-S3) :
HTTP/1.1 303 See Other
Location: /
Content-Type: text/plain

3.2. Analyse Approfondie avec Wireshark

Wireshark permet d'analyser l'intégralité du paquet réseau, en détaillant les différentes couches du Modèle OSI (Ethernet, IP, TCP, HTTP) :

  1. Lancer l'application Wireshark sur votre poste.
  2. Sélectionner l'interface réseau active (Wi-Fi).
  3. Démarrer la capture de trames.
  4. Appliquer le filtre d'affichage suivant (en remplaçant l'IP par celle de votre XIAO) :
    http && ip.addr == 192.168.1.50
  5. Effectuer une action sur la page Web (cliquer sur Allumer ou Éteindre).
  6. Interrompre la capture et analyser les paquets filtrés.

Tableau de décodage de la trame selon le Modèle OSI :

Couche / Champ Valeur observée Explication & Rôle
Couche 3 (Réseau) IP Source / IP Destination Identifie l'adresse IP de l'ordinateur client et celle du XIAO ESP32-S3 sur le réseau local.
Couche 4 (Transport) Port Destination = 80 Port de service standard réservé au protocole HTTP non sécurisé.
Méthode HTTP GET Type de requête HTTP demandant une action ou une ressource au serveur.
URI demandée /led/on ou /led/off Point d'accès (route) spécifiquement ciblé pour exécuter l'action sur le GPIO 21.
Code de réponse 303 See Other Code d'état indiquant une redirection HTTP (Location: /) pour recharger l'interface.

4. PARTIE 3 : Extension HTTPS (TLS/SSL) & Résistance au Sniffing

Afin de corriger la vulnérabilité majeure de fuite de données observée en HTTP clair, cette section met en œuvre une couche de chiffrement TLS v1.2 / v1.3 sur l'ESP32.

🛡️ Objectif de la Sécurisation HTTPS

Modifier votre programme HTTP existant pour mettre en œuvre un serveur HTTPS chiffré, puis comparer la visibilité des données entre l'outil de développement du navigateur (F12) et l'analyseur de paquets Wireshark.

4.1. Pistes de Modification du Code Arduino

Conservez votre code fonctionnel précédent. Vous devez y apporter 4 modifications ciblées :

  1. Changement de bibliothèque réseau : Remplacer <WebServer.h> par la bibliothèque gérant le chiffrement TLS/SSL : <WiFiClientSecure.h>. 
    #include <WiFi.h>
#include <WiFiClientSecure.h> // Remplace WebServer.h pour gérer le TLS/SSL
#include <WiFiManager.h>
  2. Déclaration du certificat X.509 et de la clé privée : Ajouter en haut du sketch (au-dessus du setup) les variables contenant le certificat auto-signé et la clé privée au format PEM : 
    // -------------------------------------------------------------------
// 1. Certificat X.509 auto-signé et clé privée (Format PEM)
// -------------------------------------------------------------------
const char* server_cert = 
"-----BEGIN CERTIFICATE-----\n"
"MIIDATCCAe2gAwIBAgIUYR1234567890ABCDEFGHIJKLMNOP\n"
"-----END CERTIFICATE-----\n";

const char* server_key = 
"-----BEGIN PRIVATE KEY-----\n"
"MIIEvgIBADANBgkqhkiG9w0BAQEFAASCBKgwggSkAgEAAoI\n"
"-----END PRIVATE KEY-----\n";
  3. Changement de port et instanciation du serveur : Déclarer le serveur sécurisé sur le port standard HTTPS (443) en utilisant l'objet WiFiServerSecure au lieu de WebServer : 
    // Le serveur écoute désormais sur le port sécurisé 443 (HTTPS)
WiFiServerSecure secureServer(443);
  4. Configuration du chiffrement dans la fonction setup() : Avant d'appeler begin(), associer les clés de chiffrement au serveur sécurisé : 
    secureServer.setCertificate(server_cert);
secureServer.setPrivateKey(server_key);
secureServer.begin();

📌 Constatation de Sécurité & Cryptographie

Le filtre http ne renvoie plus aucun résultat car l'intégralité des en-têtes et du payload HTTP est chiffrée au sein de la couche TLS Record Layer. La recherche des octets magiques (ex: FF D8 FF pour les images JPEG) dans le flux TLS échoue : les données présentent une entropie élevée assimilable à un bruit aléatoire. Le menu Fichier > Exporter des objets > HTTP sous Wireshark n'extrait aucun objet.
