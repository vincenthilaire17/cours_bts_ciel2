🎯 Objectif Pédagogique de cette Fiche de Référence

Cette fiche ressource fournit le mémento technique indispensable pour repérer la structure bit à bit et octet par octet des en-têtes réseau lors de l'analyse de trames sous Wireshark et lors des épreuves de conception / validation du BTS CIEL.

1. Vue d'Ensemble de l'Encapsulation

Lorsqu'une commande HTTP (ex: GET /led/on) est émise depuis un navigateur ou un client vers l'ESP32 / Pico W, la donnée applicative descend l'ensemble de la pile de protocoles du Modèle OSI. Chaque couche entoure le message de son propre en-tête (Header) :

+---------------------------------------------------------------------------------------------------+
| Trame Ethernet II (Couche 2 - Liaison de données)                                                 |
| +---------------------------------------------------------------------------------------------+   |
| | Paquet IPv4 (Couche 3 - Réseau)                                                             |   |
| | +---------------------------------------------------------------------------------------+   |   |
| | | Segment TCP / UDP (Couche 4 - Transport)                                              |   |   |
| | | +---------------------------------------------------------------------------------+   |   |   |
| | | | Message HTTP / Données Utiles (Couche 7 - Application)                          |   |   |   |
| | | | "GET /led/on HTTP/1.1\r\nHost: 192.168.1.50..."                                 |   |   |   |
| | | +---------------------------------------------------------------------------------+   |   |   |
| | +---------------------------------------------------------------------------------------+   |   |
| +---------------------------------------------------------------------------------------------+   |
+---------------------------------------------------------------------------------------------------+

2. Structure Détaillée des En-Têtes (Format RFC)

2.1. Trame Ethernet II (Couche 2 — Liaison de données)

La trame Ethernet II (standard IEEE 802.3 / DIX) n'utilise pas la grille de 32 bits classique du monde IP car ses champs d'adresses physiques (adresses MAC) s'alignent sur 6 octets (48 bits) :

    OCTET 0         OCTET 1         OCTET 2         OCTET 3     
 0 1 2 3 4 5 6 7 0 1 2 3 4 5 6 7 0 1 2 3 4 5 6 7 0 1 2 3 4 5 6 7
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                       MAC Destination                         |
|                          (6 octets)                           |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                          MAC Source                           |
|                          (6 octets)                           |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|     EtherType (2 octets)      |                               |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+                               |
|                                                               |
|                  Payload / Donnée IPv4 (L3)                   |
|                      (46 à 1500 octets)                       |
|                                                               |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                          FCS / CRC32                          |
|                           (4 octets)                          |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+

Valeurs clés à observer dans Wireshark :

  • MAC Destination : Adresse physique de la carte réseau cible (ex: 68:B6:B3:45:12:34 pour l'ESP32 ou la passerelle).
  • MAC Source : Adresse physique de la carte réseau de l'ordinateur émetteur.
  • EtherType (Type de protocole encapsulé) :
    • 0x0800 = IPv4 (Valeur standard observée dans les TP Web/MQTT)
    • 0x86DD = IPv6
    • 0x0806 = ARP (Address Resolution Protocol)
  • FCS (Frame Check Sequence) : Somme de contrôle cyclique CRC32 (souvent vérifiée et retirée par la carte réseau matérielle avant la capture logicielle).

2.2. En-tête IPv4 (Couche 3 — Réseau)

Conforme au standard RFC 791. Chaque ligne horizontale du diagramme représente exactement 32 bits (4 octets) :

    OCTET 0         OCTET 1         OCTET 2         OCTET 3     
 0 1 2 3 4 5 6 7 0 1 2 3 4 5 6 7 0 1 2 3 4 5 6 7 0 1 2 3 4 5 6 7
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|Version|  IHL  |Type of Service|          Total Length         |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|         Identification        |Flags|      Fragment Offset    |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|  Time to Live |    Protocol   |        Header Checksum        |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                       Source IP Address                       |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                    Destination IP Address                     |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                    Options (si IHL > 5)       |    Padding    |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+

Champs prioritaires pour l'analyse sous Wireshark :

  • Version (4 bits) : Toujours 4 pour IPv4 (valeur hexadécimale du premier quartet = 0x4).
  • IHL (Internet Header Length - 4 bits) : Nombre de mots de 32 bits de l'en-tête (généralement 5, soit $5 \times 4 = 20\text{ octets}$). La combinaison Version + IHL donne souvent l'octet 0x45.
  • Total Length (16 bits) : Taille totale du paquet IP en octets (En-tête IP + Données L4).
  • Time to Live - TTL (8 bits) : Nombre maximal de routeurs traversables (décrémenté à chaque saut pour éviter les boucles infinies).
  • Protocol (8 bits - Offset 0x17) : Identifie le protocole de couche supérieure transporté :
    • 6 (0x06) = TCP (Utilisé par HTTP, HTTPS, MQTT, SSH)
    • 17 (0x11) = UDP (Utilisé par DNS, DHCP, NTP, CoAP)
    • 1 (0x01) = ICMP (Ping, messages d'erreurs)
  • Source IP Address (32 bits) : Adresse IP du PC client (ex: 192.168.1.20 ou C0 A8 01 14).
  • Destination IP Address (32 bits) : Adresse IP du serveur ESP32 (ex: 192.168.1.50 ou C0 A8 01 32).

2.3. En-tête TCP (Couche 4 — Transport pour HTTP)

Le protocole HTTP s'appuie sur TCP (RFC 793 / RFC 9293), qui garantit une communication fiable, ordonnée et bidirectionnelle :

    OCTET 0         OCTET 1         OCTET 2         OCTET 3     
 0 1 2 3 4 5 6 7 0 1 2 3 4 5 6 7 0 1 2 3 4 5 6 7 0 1 2 3 4 5 6 7
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|          Source Port          |       Destination Port        |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                        Sequence Number                        |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                    Acknowledgment Number                      |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|  Data |           |U|A|P|R|S|F|                               |
| Offset| Reserved  |R|C|S|S|Y|I|            Window             |
|       |           |G|K|H|T|N|N|                               |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|           Checksum            |        Urgent Pointer         |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                    Options (si nécessaire)    |    Padding    |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                             Data                              |
|                  (Requête HTTP Applicative)                   |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+

Champs prioritaires pour l'analyse sous Wireshark :

  • Source Port (16 bits) : Port dynamique temporaire (éphémère) alloué par le système d'exploitation du client (ex: 54321).
  • Destination Port (16 bits) :
    • 80 (0x0050) = HTTP (Serveur Web en clair)
    • 443 (0x01BB) = HTTPS (Serveur Web sécurisé par TLS)
    • 1883 (0x075B) = MQTT (Broker Mosquitto)
  • Sequence Number (32 bits) : Numérote le premier octet de données envoyé dans le segment.
  • Acknowledgment Number (32 bits) : Numéro du prochain octet que le récepteur s'attend à recevoir.
  • Flags (Drapeaux de contrôle) :
    • SYN (0x02) : Demande initiale de synchronisation et d'établissement de connexion.
    • ACK (0x10) : Confirmation de bonne réception des octets précédents.
    • PSH (0x08) : Demande de transmission immédiate des données à l'application sans mise en tampon.
    • FIN (0x01) : Demande formelle de fermeture de session TCP.
    • RST (0x04) : Réinitialisation immédiate en cas d'erreur de connexion.

2.4. Comparatif : En-tête UDP (Couche 4 — Transport alternatif)

À titre comparatif, UDP (RFC 768) est un protocole minimaliste sans connexion, sans poignée de main et sans acquittement, privilégié pour les flux temps réel et les capteurs IoT contraints :

    OCTET 0         OCTET 1         OCTET 2         OCTET 3     
 0 1 2 3 4 5 6 7 0 1 2 3 4 5 6 7 0 1 2 3 4 5 6 7 0 1 2 3 4 5 6 7
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|          Source Port          |       Destination Port        |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|            Length             |           Checksum            |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                             Data                              |
|                   (Payload applicatif UDP)                    |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
⚡ Comparaison d'Overhead Couche 4 (TCP vs UDP)

L'en-tête standard UDP ne pèse que 8 octets, contre 20 octets au minimum pour TCP (sans options). UDP n'effectue aucun 3-Way Handshake préalable, ce qui permet d'émettre une commande en une seule trame réseau.

3. Payload Application : Contenu du Message HTTP (Couche 7)

Le payload transporté au sein du segment TCP contient les données brutes sous forme de texte ASCII en clair (cleartext).

3.1. Structure d'une Requête HTTP GET (Commande de la LED)

+---------------------------------------------------------------------------------+
| GET /led/on HTTP/1.1\r\n                                                        |
| Host: 192.168.1.50\r\n                                                          |
| User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)\r\n                       |
| Accept: text/html,application/xhtml+xml,application/xml\r\n                    |
| Referer: http://192.168.1.50/\r\n                                               |
| \r\n                                                                            |
+---------------------------------------------------------------------------------+
💡 Règle de Fin d'En-tête HTTP

En HTTP/1.1, la fin de la section des en-têtes est impérativement marquée par une ligne vide, soit la séquence de caractères de contrôle \r\n\r\n (en hexadécimal : 0D 0A 0D 0A).

3.2. Repérage Hexadécimal dans Wireshark (Panneau des Octets)

Dans la vue hexadécimale de Wireshark (panneau inférieur), vous pouvez retrouver directement la séquence d'octets ASCII correspondant au chemin d'URL demandé :

A. Commande "Allumer la LED" (/led/on)

Hexadécimal : 2F 6C 65 64 2F 6F 6E
ASCII       :  /  l  e  d  /  o  n

B. Commande "Éteindre la LED" (/led/off)

Hexadécimal : 2F 6C 65 64 2F 6F 66 66
ASCII       :  /  l  e  d  /  o  f  f

4. Tableau Récapitulatif pour l'Analyse Wireshark

Ce tableau résume les champs clés à vérifier dans l'arborescence des protocoles de Wireshark lors des manipulations de laboratoire :

Niveau OSI Protocole Champ à observer dans Wireshark Valeur attendue dans les TP CIEL
L2 (Liaison) Ethernet II EtherType 0x0800 (IPv4)
L3 (Réseau) IPv4 Protocol 6 (TCP) ou 17 (UDP)
L3 (Réseau) IPv4 Source / Destination IP Client (PC) / IP Serveur (ESP32 / Pico W)
L4 (Transport) TCP Destination Port 80 (HTTP en clair) / 443 (HTTPS / TLS)
L4 (Transport) TCP Flags 0x02 (SYN), 0x10 (ACK), 0x18 (PSH + ACK)
L4 (Transport) UDP (Alternatif) Destination Port 4210 (Port d'écoute direct sans connexion)
L7 (Application) HTTP Request Method GET ou POST
L7 (Application) HTTP Request URI /led/on ou /led/off
L7 (Application) HTTP Response Code 303 See Other (Redirection) ou 200 OK
🔍 Astuces de Filtrage Rapide sous Wireshark
  • Filtrer uniquement le trafic de votre carte : ip.addr == 192.168.1.50
  • Filtrer les requêtes HTTP : http.request.method == "GET"
  • Filtrer le port HTTP : tcp.port == 80
  • Filtrer le port HTTPS / TLS : tcp.port == 443 || tls
  • Filtrer le port UDP de commande : udp.port == 4210
  • Reconstruire le dialogue complet : Clic droit sur un paquet > Suivre > Flux TCP (Follow TCP Stream).
