1. Pourquoi le Code PIN Bluetooth à 4 chiffres est-il si vulnérable ?

Dans les modules Bluetooth industriels économiques de type SPP (HC-05, HC-06, HM-10 ou Grove Bluetooth v3.0), le mécanisme d'authentification utilisé est le protocole historique Legacy Pairing (spécification Bluetooth ≤ 2.0/2.1).

Ce protocole présente deux vulnérabilités fondamentales :

  1. L'espace des clés est dérisoire : Un code PIN à 4 chiffres décimaux (de 0000 à 9999) ne représente que :
    Espace des clés = 104 = 10 000 combinaisons possibles (≈ 13,3 bits d'entropie)
  2. Le protocole transmet des informations dérivées en clair : Lors de la négociation d'appairage, les deux équipements échangent publiquement leurs adresses matérielles MAC (BD_ADDR) et des nombres aléatoires (IN_RAND). Un attaquant passif qui écoute les trames radio peut exécuter une attaque hors-ligne (offline brute-force) à une vitesse de plusieurs millions de combinaisons par seconde.

4. Comment fonctionne l'outil de référence btcrack

Le logiciel libre btcrack (développé initialement par Thierry Zoller) est l'outil canonique utilisé pour démontrer la faiblesse de l'algorithme d'authentification Bluetooth E22 (basé sur le chiffrement par bloc SAFER+).

📋 Algorithme mathématique de dérivation E22

Pour chaque entier PIN candidat entre 0000 et 9999 :

  1. Calculer la clé d'initialisation candidate : K_cand = E22(PIN, IN_RAND, BD_ADDR_esclave)
  2. Calculer la réponse d'authentification candidate : SRES_cand = E1(K_cand, AU_RAND, BD_ADDR_maitre)
  3. Comparer SRES_cand avec le SRES_capture intercepté lors du sniffing.
  4. Si égalité : le PIN candidat est garanti exact à 100% !

Exemple de commande d'audit sous console Linux / Kali :

6. Synthèse & Corrigé Synthétique (Repères Enseignant)

✅ Éléments de Correction :
  • Question E.1 :
    • H = log2(10 000) = 13,28 bits. C'est une entropie extrêmement faible qui ne résiste à aucune attaque computationnelle moderne.
    • Pour 12 caractères choisis parmi 62 symboles : 6212 ≈ 3,22 × 1021 combinaisons (≈ 71,4 bits d'entropie). Même à 1 milliard de tests par seconde, il faudrait plus de 100 000 ans pour tester toutes les combinaisons.
  • Question E.2 :
    • Secure Simple Pairing (SSP) : Utilise un échange de clés à clé publique ECDH (Elliptic Curve Diffie-Hellman, courbe P-256). Les deux équipements négocient une clé secrète partagée sans jamais faire transiter le secret sur la liaison radio. Un écouteur passif qui capture tous les échanges ne peut rien dériver sans résoudre le problème du logarithme discret sur courbes elliptiques.
    • Contre-mesure active contre l'attaque en ligne : Implémenter un délai exponentiel (Rate Limiting) ou un blocage temporaire (verrouillage de 5 minutes après 3 tentatives infructueuses de connexion).
