📋 Contexte Industriel du Projet

Dans les environnements industriels et biomédicaux, la maintenance et le paramétrage d'équipements scellés ou difficiles d'accès s'effectuent sans liaison physique, au moyen d'un lien sans fil sécurisé à courte portée (Bluetooth). Vous êtes chargé de développer et de qualifier le sous-système de communication d'un pupitre de télé-exploitation sécurisé.

Le système embarqué repose sur la nouvelle génération Raspberry Pi Pico 2 W (microcontrôleur RP2350 Dual Cortex-M33 / RISC-V), enfichée sur son Grove Shield pour Pi Pico. Elle dialogue avec un module Grove Serial Bluetooth connecté sur le port UART1 (GP4/GP5), et un Grove I²C Hub mutualisant un clavier capacitif 12 touches, un écran OLED et une matrice de LED 8x8. La qualification temporelle et le décodage de trames sont réalisés avec l'analyseur logique mixte Digilent Analog Discovery 3 piloté par WaveForms.

0. Procédure Préalable : Remise à Zéro de la Mémoire Flash (Nuke Universal)

Les cartes Raspberry Pi Pico 2 W utilisées en atelier peuvent contenir des résidus de firmwares précédents (MicroPython, CircuitPython) ou des tables de partitions LittleFS qui occupent le contrôleur USB et bloquent la détection du port COM virtuel sous Arduino IDE.

🧹 Pourquoi flasher avec nuke_universal.uf2 ?

Le fichier nuke_universal.uf2 (compatible architectures RP2040 et RP2350 du Pico 2) est un utilitaire officiel qui écrit la valeur 0xFF sur l'intégralité des secteurs de la mémoire flash QSPI (4 Mo). Il efface tout résidu de code bloquant et force le microcontrôleur à redémarrer immédiatement dans son chargeur de démarrage matériel (ROM Bootloader).

Méthode de Hard Reset pas-à-pas :

  1. Déconnectez le câble USB de la carte Raspberry Pi Pico 2 W.
  2. Maintenez enfoncé le bouton blanc BOOTSEL situé directement sur la carte Pico 2 W.
  3. Tout en maintenant BOOTSEL enfoncé, branchez le câble USB au port de votre ordinateur, puis relâchez le bouton après 2 secondes.
  4. Vérifiez l'ouverture d'un nouveau lecteur de disque amovible dans Windows nommé RP2350 (ou RPI-RP2).
  5. Glissez-déposez le fichier nuke_universal.uf2 directement sur ce lecteur :
    • La LED verte du Pico clignote brièvement pendant l'effacement complet.
    • Dès la fin de l'opération, la carte redémarre toute seule et le lecteur USB réapparaît vierge, prêt à recevoir votre programme compilé depuis l'Arduino IDE.

💡 Architecture Matérielle RP2350 : Double UART Matériel & Hub I²C

1. Affectation des liaisons séries UART :
Le RP2350 possède deux contrôleurs UART matériels indépendants :

  • UART0 (GP0 / GP1) : géré par Serial1.
  • UART1 (GP4 / GP5) : géré par Serial2. C'est sur ce port que le module Bluetooth est connecté.
La console de débogage PC s'effectue via l'interface USB native (Serial à 115200 bauds).

2. Mutualisation du Bus I²C et Point de Test :
Le port I2C0 du Grove Shield (GP8=SDA, GP9=SCL) est relié au Grove I2C Hub. Les 3 périphériques (OLED, Clavier, Matrice) y sont connectés en parallèle. Le 4e port disponible du Hub constitue un point de test (Test Point) pour brancher les sondes de l'Analog Discovery 3 (DIO 2 et DIO 3) sans risque de faux contact.

PARTIE 1 : Configuration AT du Module Bluetooth et Décodage UART sous Digilent WaveForms Durée estimée : 1h00
💡 Pourquoi utilise-t-on des commandes AT (Attention Commands) ?

À sa sortie d'usine, le module Bluetooth possède des paramètres génériques standardisés (nom d'usine anonyme type HMSoft ou BT-05, code PIN par défaut 1234, vitesse 9600 bauds, mode esclave). Dans un atelier ou une salle de TP regroupant une quinzaine de pupitres, si tous les modules conservent leur nom par défaut, il est impossible pour un opérateur d'identifier et de cibler son propre équipement lors du scan Bluetooth sur smartphone !

Les commandes AT (héritées du protocole historique des modems Hayes) permettent donc de paramétrer le module Bluetooth sur-mesure selon notre besoin avant toute mise en service opérationnelle :

  • Personnaliser l'identifiant radio : attribuer un nom d'équipement unique par binôme (ex : AT+NAMECIEL_PUPITRE_01).
  • Sécuriser l'accès physique : remplacer le code d'appairage d'usine par un code PIN confidentiel propre à l'application (ex : AT+PIN4826).
  • Définir le rôle réseau : forcer le mode Esclave (Slave) pour attendre la connexion d'un superviseur, ou Maître (Master) pour initier une liaison vers un autre capteur.
  • Optimiser les performances : ajuster la vitesse en bauds de l'UART pour accélérer les transferts de télémétrie.

Règle clé des deux modes : Tant que le module n'est pas connecté à un smartphone (LED clignotante), il est en Mode Commande et traite les instructions AT. Dès que l'application mobile s'y connecte (LED fixe), le module bascule automatiquement en Mode Données (Transparent) : il n'interprète plus les commandes AT et transmet les octets directement par les ondes radio.

Pour effectuer cette configuration, nous utiliserons un programme passerelle sur le Raspberry Pi Pico 2 W et qualifierons les échanges avec l'analyseur logique mixte Digilent Analog Discovery 3.

3.1. Guide de mise en route de Digilent WaveForms (Outil Logic Analyzer) :

  1. Connectez l'Analog Discovery 3 au port USB du PC et lancez le logiciel Digilent WaveForms.
  2. Dans la fenêtre d'accueil de WaveForms, sélectionnez votre périphérique Analog Discovery 3 puis cliquez sur Logic (Analyseur Logique).
  3. Ajoutez un décodeur de protocole : cliquez sur + (Add) $\rightarrow$ UART.
  4. Configurez les propriétés du protocole UART dans le volet :
    • TX (Émission Pico vers Bluetooth) : Sélectionner DIO 1 (Broche GP4 du Pico).
    • RX (Réception réponse Bluetooth) : Sélectionner DIO 0 (Broche GP5 du Pico).
    • Baud Rate : 9600 bauds.
    • Format : 8 Bits, Parity : None, Stop : 1 Bit.
  5. Réglez le déclenchement (Trigger) : configurez la condition sur DIO 1 en Falling Edge (Front descendant ⮧) pour déclencher l'acquisition dès l'apparition du bit de Start de la commande émise.
  6. Réglez la base de temps : Fréquence d'échantillonnage à 1 MHz ou 2 MHz et durée totale de capture à 50 ms.

3.2. Code Passerelle USB-Série & Configuration du Moniteur Série :

Le Raspberry Pi Pico 2 W exécute le programme passerelle ci-dessous en exploitant Serial2 sur les broches GP4 (TX) et GP5 (RX) du port UART1 :

/* =========================================================================
   BTS CIEL - Passerelle de commandes AT pour Raspberry Pi Pico 2 W & Grove Bluetooth
   Matériel : Raspberry Pi Pico 2 W (RP2350) + Grove Shield (Port UART1)
   Broches  : GP4 (TX Pico -> RX Bluetooth), GP5 (RX Pico <- TX Bluetooth)
   ========================================================================= */

// Sur le Raspberry Pi Pico 2 W :
// Serial  = Liaison série virtuelle USB vers l'ordinateur
// Serial2 = Port UART1 matériel sur les broches GP4 (TX) et GP5 (RX)
#define BT_SERIAL Serial2

const long BAUD_PC = 115200;  // Vitesse de la console série du PC (USB)
const long BAUD_BT = 9600;    // Vitesse d'usine du module Grove Bluetooth

void setup() {
  // 1. Démarrage de la liaison série USB (PC)
  Serial.begin(BAUD_PC);

  // 2. Démarrage du port UART1 matériel relié au module Bluetooth
  BT_SERIAL.setTX(4);         // GP4 = TX sur le port UART1 du Grove Shield
  BT_SERIAL.setRX(5);         // GP5 = RX sur le port UART1 du Grove Shield
  BT_SERIAL.begin(BAUD_BT);

  // Attente que le moniteur série USB soit ouvert (max 3 secondes)
  unsigned long start = millis();
  while (!Serial && (millis() - start < 3000));

  Serial.println("\r\n================================================");
  Serial.println("  Raspberry Pi Pico 2 W - Passerelle Commandes AT");
  Serial.println("================================================");
  Serial.println("Module Bluetooth connecte sur UART1 (GP4/GP5)");
  Serial.println("Vitesse Bluetooth : 9600 bauds");
  Serial.println("Pret ! Tapez 'AT' et appuyez sur Entree pour tester.");
  Serial.println("------------------------------------------------");
}

void loop() {
  // 1. Ce que vous tapez dans le moniteur série est envoyé au module Bluetooth
  while (Serial.available() > 0) {
    char c = (char)Serial.read();
    BT_SERIAL.write(c);
  }

  // 2. Ce que répond le module Bluetooth est affiché sur votre écran
  while (BT_SERIAL.available() > 0) {
    char c = (char)BT_SERIAL.read();
    Serial.write(c);
  }
}
⚠️ Réglage Critique du Moniteur Série : "No line ending"

Ouvrez le Moniteur Série (Serial Monitor) de l'Arduino IDE ou de l'Arduino Cloud Web Editor et configurez impérativement :

  • Fin de ligne (Line Ending) : Sélectionnez No line ending (Pas de fin de ligne).
    Ce module Bluetooth (firmware type HM-10 / HC-06) valide la commande par temporisation (délai inter-caractères) et refuse les caractères de fin de ligne (\r\n). Si vous laissez un terminateur, le module l'interprète comme des caractères corrompus et reste silencieux !
  • Vitesse USB : Réglez sur 115200 baud.

PARTIE 4 : Conception d'un Protocole Industriel avec Détection d'Erreurs (FSM) Durée estimée : 1h00

En milieu industriel, les transmissions sans fil sont soumises aux perturbations électromagnétiques. Vous devez implémenter un protocole à encapsulation binaire/ASCII sécurisé par une somme de contrôle (Checksum XOR / LRC).

Format de la trame normalisée :

Délimiteur Début ID Émetteur Code Commande Longueur (N) Données (Payload) Checksum (XOR) Délimiteur Fin
$ (0x24) 0x01 0x10 (Ordre) 0x02 (2 octets) Ex: 'O', 'N' 1 octet (LRC) # (0x23)

Travail demandé :

  1. Tracez le diagramme de la Machine à États Finis (FSM) chargée de décoder cette trame (États : WAIT_START, READ_HEADER, READ_PAYLOAD, VERIF_CHECKSUM, EXECUTE_COMMAND).
  2. Écrivez la fonction de calcul du Checksum XOR sur l'ensemble des octets compris entre le délimiteur de début et le checksum.
  3. Implémentez l'automate en langage C/C++. En cas d'erreur de checksum, le système doit rejeter la trame, afficher une alerte sur l'OLED et renvoyer NACK_CHECKSUM_ERROR\r\n.
